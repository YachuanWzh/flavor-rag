# flavor-rag v0.0.5 企业级 RAG 加固规格（SDD）

## 1. 目标

v0.0.5 将系统从功能型 RAG 原型加固为可安全试生产的 RAG 平台。本规格不讨论登录、授权与租户权限，聚焦知识摄取、索引、检索、生成、评测、可观测性和部署可靠性。

## 2. 核心不变量

### 2.1 索引生命周期

- embedding 维度或模型变化不得删除当前活动 collection。
- 写入维度与活动 collection 不兼容时必须显式失败，并给出重建指引。
- 重建使用新的 generation collection；完成数量和维度校验后才允许切换活动 alias。
- 每个索引 generation 持久化 embedding 模型、维度、parser 版本、chunker 版本和状态。
- 删除旧 generation 必须是显式、延迟且可审计的运维动作。

### 2.2 摄取一致性

- 摄取任务以稳定 idempotency key 去重，同一任务重试不得产生重复 chunk。
- 文档新 generation 在 PG、Milvus 和所有 required channel 成功前不可激活。
- optional channel 失败必须记录待修复状态，不得伪装为成功。
- 重处理失败时，旧 generation 保持可检索。
- 系统提供 PG 与外部索引的对账、补偿和完整重建入口。

### 2.3 检索正确性

- 推测式检索结果只能在查询文本和最终 collection 均一致时复用。
- 顺序和并行执行路径支持相同的 HyDE、路由、超时与追踪语义。
- 检索通道异常必须进入 channel status、指标和熔断器，不得转换为成功空结果。
- RRF、向量和 reranker 分数不得共用未经校准的绝对阈值。
- 上下文预算使用模型 token 估算，并包含 system、history、memory、profile 和 evidence。

### 2.4 生成与引用

- 检索内容作为不可信 evidence 注入，不能覆盖系统指令。
- 每个外部可验证论断应有可解析引用；引用必须指向实际提供的 evidence。
- 流式展示、finish 事件与数据库持久化的最终答案完全一致。
- 生成具备总超时、最大输出 token 和断开连接取消语义。
- memory 写入只提取用户明确表达的事实，不能把 assistant 猜测固化为用户事实。

### 2.5 文档处理

- 上传必须限制单文件大小、批量文件数、页数、压缩后体积和 OCR/VLM 并发。
- 校验扩展名、MIME 和文件签名；危险或不一致输入 fail closed。
- CPU/阻塞型解析和同步向量 SDK 调用不得阻塞 ASGI 事件循环。
- 源文件使用可共享持久存储；本地存储仅允许单机开发模式。

### 2.6 评测

- 评测数据绑定 corpus snapshot、document generation、prompt、模型和索引版本。
- 同时评估 retrieval 与最终 answer。
- 至少覆盖 Recall/NDCG/MRR、answer correctness、groundedness、completeness、answer relevance、citation precision/coverage 和拒答能力。
- prompt injection 用例必须执行到生成阶段。
- 质量门禁必须检查最小样本数并报告不确定性，不能用失效 chunk ID 静默打分。

### 2.7 运行与部署

- 空 PostgreSQL 可通过单一 `alembic upgrade head` 初始化。
- 容器启动前执行 migration，使用服务 DNS，不运行 reload server。
- liveness 与 readiness 分离；readiness 检查 PG、Redis、Milvus、required search channel、对象存储和必要模型配置。
- 所有后台调度在多副本下具备可靠 leader/claim 机制；标准 cron 表达式按真实 cron 语义执行。
- 提供索引新鲜度、失败/重试、token、成本、空召回、拒答、引用和端到端延迟指标。

## 3. 失败策略

- 数据安全相关错误 fail closed：维度不匹配、required index 写入失败、generation 校验失败。
- 可降级通道 fail visible：允许主链路继续，但必须在状态、trace、指标和 repair queue 中可见。
- 调度锁故障 fail closed，避免重复执行。
- 所有重试必须幂等，并有最大次数与 DEAD 状态。

## 4. 测试策略（TDD）

- 单元测试：索引维度保护、collection 路由、引用协议、token 预算、文件限制、cron/锁语义。
- 状态机测试：摄取 generation 激活、失败回滚、重试幂等、repair job。
- 集成测试：PostgreSQL + Milvus + Elasticsearch 的写入、失败补偿、重建与查询。
- 端到端测试：上传文档到流式答案和引用，包含无答案及注入文档。
- 非功能测试：并发上传、长 PDF、服务降级、worker 崩溃恢复、readiness。
