# 面试模拟模块 - SDD

状态：实现中  
日期：2026-07-30

## 1. 目标与范围

在现有对话工作台中增加可开关的沉浸式面试模式。面试题由指定知识库
证据、用户简历、目标岗位 JD 和历史面试表现共同驱动；面试结束后生成
0-10 分的单次报告，并把结果平滑聚合为长期面试画像。

核心不变量：

1. 题目不少于 10 道，默认 12 道。
2. 材料完整时默认配额为 7 道知识库题、3 道简历/JD 交叉追问、
   2 道大厂风格场景深挖题。
3. 用户缺少简历或 JD 时不减少总题数，空缺配额由知识库和场景题回填。
4. 选择单一知识库时，检索、题目证据与复盘来源必须严格限制在该库。
5. 知识库证据沿用现有 RAG ACL、来源字段和 PDF 页码/坐标预览能力。
6. 没有可用证据时必须标记为 Agent 自拟题，不得伪造知识库来源。
7. 简历和 JD 的 SHA-256 相同即视为未更新；文件名变化不触发重分析。
8. 面试过程中不展示评分、参考答案和完整评分点，全部提交后统一复盘。
9. 原始材料只对当前用户可见，不写日志、不进入公共知识库，并提供删除能力。

## 2. 用户流程

### 2.1 准备

用户在对话页开启“面试模式”，进入面试准备抽屉：

- 选择“全部可访问知识库”或某一个专项知识库；
- 上传 PDF 简历，可跳过；
- 上传 PDF/DOCX/TXT/Markdown 岗位 JD，或直接粘贴 JD，可跳过；
- 选择面试难度：中级、高级、专家；
- 选择题目数，范围 10-20，默认 12；
- 填写“本场重点”，例如“偏重 Agent 规划、RAG 检索评估和项目深挖”；该约束与简历、
  JD、知识库证据共同参与检索和出题，优先级为用户重点 > 简历经历 > JD > 知识库泛化；
- 目标岗位或本场重点为空时，点击进入面试房间会先把界面占位提示回填为实际值，再使用
  该默认值生成题目；
- 页面显示材料哈希判断结果：“已更新”或“内容未变化”。

### 2.2 面试

开始后主区切换为沉浸式面试房间：

- 顶栏显示岗位、知识库、难度、总计时和题目进度；
- 单次只展示一题，题目带类型标签，不泄露答案；
- 顶部展示可点击题卡盘：未作答显示题号，已作答显示勾选，当前题高亮；切题时保留
  未提交草稿，提交后自动跳到下一道未作答题；
- 输入自然语言答案后点击“我答完了”进入下一题；
- 允许跳过单题或提前结束，跳过题按未作答计分；
- “暂时离开”只关闭面试页并保留恢复入口；“退出本场”需二次确认，退出后状态改为
  `ABANDONED`，本场不评分、不更新画像，也不出现在最近已完成面试中；
- 知识库来源在面试中仅显示“有证据”，结束后才开放文档复盘。

### 2.3 复盘

全部题目回答完毕后生成：

- 总分（0-10，允许一位小数）；
- 六维能力雷达图；
- 相比上一次面试的上升、下降或稳定；
- 岗位匹配度，以及硬技能覆盖、项目证据、职责匹配和难度匹配；
- 每题得分、答案分析、改进建议、参考要点；
- 每题对应知识库来源，可打开现有来源抽屉与 PDF 定位。

### 2.4 历史回溯

- 面试准备页和单次复盘页均可进入“历史回溯”；
- 时间轴只展示 `COMPLETED` 面试，按完成时间倒序排列，`ABANDONED` 不参与；
- 每个节点展示完成时间、岗位、知识库、难度和 0-10 总分；
- 点击节点后加载该次完整表现，展示六维得分、总评和岗位匹配结果；
- “重点复盘”区域按单题分数升序展示最低 3 题，至少包含问题、用户原回答、单题得分、
  分析和改进建议；跳过题也作为低分题展示；
- 历史页支持清空，需二次确认；清空会删除已完成/已退出面试及其题目、回答、评分，
  同时重置派生的面试能力画像，但不得影响当前进行中的面试和已上传简历/JD；
- 历史为空时展示明确空状态并引导开始第一次模拟。

## 3. 评分模型

默认维度与权重（服务端常量，前端从 API 读取，便于确认后调整）：

| 维度 | key | 权重 |
| --- | --- | ---: |
| 知识准确度 | knowledgeAccuracy | 25% |
| 原理与技术深度 | technicalDepth | 20% |
| 实践与落地能力 | practicalApplication | 20% |
| 分析解决能力 | problemSolving | 15% |
| 表达结构性 | communication | 10% |
| 岗位匹配度 | roleFit | 10% |

单次总分为维度加权平均，四舍五入到一位小数。长期画像使用指数平滑：

`new = previous * 0.65 + current * 0.35`

首次面试直接使用本次分数。总分变化绝对值小于 0.3 视为“稳定”。

岗位匹配度由四个子项汇总：

- 硬技能覆盖 35%
- 项目证据 30%
- 职责匹配 20%
- 难度匹配 15%

## 4. 数据模型

### t_interview_material

每个用户每种材料保留当前版本，字段包含：
`user_id`、`tenant_id`、`kind`、`file_name`、`content_hash`、
`extracted_text`、`mime_type`、`file_size`、`updated_at`。

### t_interview_session

记录面试范围和状态：
`user_id`、`kb_id`、`kb_name`、`target_role`、`user_focus`、`difficulty`、`question_count`、
`resume_hash`、`jd_hash`、`status`、`overall_score`、
`dimension_scores`、`role_fit_breakdown`、`summary`、
`started_at`、`completed_at`。

### t_interview_question

记录题目、类别、追问提示、评分要点、知识库来源快照和显示顺序。
来源使用与现有 `SourceRef` 相同的 camelCase 结构。

### t_interview_answer

每题一个答案，记录文本、是否跳过、单题分数、维度分、分析、优点、
改进建议和参考要点。

### t_interview_profile

每用户一条长期画像，记录六维平滑分、总分、上次变化量、趋势、
面试次数、目标岗位和更新时间。

## 5. API

- `GET /api/interviews/config`：题数范围、难度和评分维度。
- `GET /api/interviews/materials`：当前材料状态，不返回全文。
- `POST /api/interviews/materials/{resume|jd}`：上传材料并返回哈希状态。
- `POST /api/interviews/materials/jd-text`：保存粘贴的 JD。
- `DELETE /api/interviews/materials/{resume|jd}`：删除私有材料。
- `POST /api/interviews`：检索证据并生成题目。
- `GET /api/interviews/history`：查询当前用户已完成面试时间轴摘要。
- `DELETE /api/interviews/history`：清空历史面试与派生画像，保留进行中面试和材料。
- `GET /api/interviews/{id}`：恢复进行中面试。
- `PUT /api/interviews/{id}/answers/{question_id}`：暂存答案。
- `POST /api/interviews/{id}/abandon`：确认退出，不评分且不计入画像。
- `POST /api/interviews/{id}/submit`：统一评分并更新长期画像。
- `GET /api/interviews/profile/me`：当前用户面试画像与最近记录。
- `GET /api/admin/profiles/{user_id}/interview`：管理员画像页查看。

## 6. 生成与检索

1. 用用户重点、JD 技能词、简历项目词和难度构造受限检索查询；
2. 使用现有 RAG Pipeline 和用户 ACL 解析可读知识库范围；
3. 指定知识库时只传入该知识库的 retrieval scope；
4. RAG 外部通道不可用时使用关系库中已授权、启用且未删除的分块做
   词项回退检索；
5. LLM 按 JSON 合约生成问题；解析失败或 Mock 模式使用确定性模板，
   仍保留真实来源；
6. 评分时只提供题目、用户答案、评分点和引用证据，避免引入无关材料。
7. 简历存在时，先抽取项目名、技术动作、个人职责和量化结果作为“简历锚点”；至少
   70% 题目必须引用一个真实锚点，并结合知识库证据或 JD 继续追问，不允许引入材料中
   未出现且与知识库无关的技术名词。
8. 用户填写本场重点时，知识库检索查询、确定性题目模板和 LLM 改写提示都必须携带该
   约束；不得用自由发挥覆盖用户指定方向。

## 7. 状态机与错误处理

`PREPARING -> IN_PROGRESS -> SCORING -> COMPLETED`

`IN_PROGRESS -> ABANDONED`

- 已完成的面试不可再次修改答案；
- 评分失败回到 `IN_PROGRESS`，答案不丢失；
- 同一题重复保存为幂等更新；
- 材料解析失败不创建/覆盖材料记录；
- 无可访问知识库时允许 Agent 自拟，但 UI 明确提示无来源题目；
- 网络中断后可通过 `GET /api/interviews/{id}` 恢复。
- `ABANDONED` 为终态，不允许继续保存答案或提交评分，也不更新长期画像。

## 8. 验收标准

1. 对话页可开启/关闭面试模式，关闭不会删除进行中记录。
2. 相同简历/JD 内容重复上传返回 `changed=false`。
3. 默认完整材料生成 12 题且类别配额为 7/3/2。
4. 任意配置均不少于 10 题。
5. 单库面试的全部来源 `kbId` 等于选择的知识库。
6. 回答未全部提交前不返回逐题评分和参考答案。
7. 完成后总分为 0-10 一位小数，并返回六维分。
8. 第二次面试后画像展示可验证的升降变化。
9. 复盘来源可打开现有来源抽屉/PDF 页面定位。
10. 桌面端与移动端均保持完整的准备、面试和复盘流程。
11. 已回答题卡显示勾选，任意题号可点击切换，切换不会丢失本地草稿。
12. 退出本场后状态为 `ABANDONED`，画像面试次数、能力分和最近记录均不变化。
13. 有简历时至少 70% 题目能追溯到简历中的具体项目、技术动作或量化结果；填写本场
    重点后，题目同时满足该方向、所选知识库证据和 JD 岗位要求。
14. 目标岗位和本场重点留空直接开始时，请求与输入框分别使用各自的占位默认值。
15. 已上传的个人简历和岗位 JD 均可在准备页单独清空；清空前需再次确认，成功后界面
    立即恢复未上传状态，后续新面试不再使用该材料。
16. 历史时间轴按完成时间倒序展示全部已完成面试，点击节点能查看该次六维得分和总评。
17. 历史节点详情展示该次得分最低的 3 道题、用户原回答、分析与改进建议；退出的模拟
    不得出现在历史中。
18. 清空历史必须二次确认；成功后时间轴和面试画像为空，历史详情不可再访问，进行中
    面试和简历/JD 材料保持不变。
